Working Directory — yeh tumhara actual folder hai, jahan tum files edit karte ho
Staging Area — ek "to-do list" jaisa. Jo files tum commit karna chahte ho, unhe yahan rakh dete ho

git add . exactly kya karta hai
Yeh saari nayi aur badli hui files ko working directory se utha kar staging area mein daal deta hai.



. (dot) ka matlab hai — current folder aur uske andar sab kuch, recursively
Nayi files, modified files, deleted files — sab stage ho jaate hain
Sirf woh files jinko tumne .gitignore mein ignore kiya hai, woh chhoot jaati hain
Tumhare project mein, agar tumne pom.xml, LoginTest.java, testng.xml, aur ci.yml banayi hain, toh git add . yeh chaaron ko stage kar dega — ek-ek karke add karne ki zaroorat nahi.



git add . vs git add <filename>
git add pom.xml → sirf ek file stage hoti hai
git add . → sab kuch stage hota hai
git add . isliye popular hai kyunki pehli baar setup karte waqt tumhe saari files commit karni hoti hain — ek-ek karke add karna tedious hai.



Iske baad kya hota hai
Yeh akela kaafi nahi hai. git add sirf tayyari karta hai. Changes save karne ke liye commit karna padta hai:




bash
git add .                          # sab stage karo
git commit -m "first CI pipeline"  # stage ki hui cheezein save karo
git add ke bina git commit karoge toh Git kahega "nothing staged" — kyunki usse pata hi nahi kya save karna hai.



Ek check karne ka tareeka
git add . ke baad, yeh chala kar dekh sakte ho ki kya-kya stage hua:



bash
git status
Green mein woh saari files dikhengi jo staged hain. Jo red mein hain, woh abhi bhi unstaged hain.

Interview point
Ek common question: "git add . aur git commit mein kya farak hai?"

"git add files ko staging area mein daalta hai — yeh tayyari ka step hai. git commit un staged changes ka ek permanent snapshot banata hai. Dono alag hain — stage kiye bina commit nahi hota."

Toh simple bhasha mein: git add . = "yeh saare changes main save karna chahta hoon, inhe taiyaar rakho" — par abhi save nahi hua, bas taiyaar hua. Save git commit se hoga.

1. git branch -M main
css
git branch -M main
Ye kya karta hai:

Git me jab tum git init karte ho, to by default tumhari pehli branch ka naam master hota hai (Git ki purani convention). Lekin GitHub aajkal main naam expect karta hai — naya standard yahi hai.

-M ka matlab hai "Move/Rename branch, forcefully".

-m (chhota) = rename, lekin agar main naam ki branch pehle se exist karti ho to error dega.
-M (bada) = rename, aur agar main pehle se ho to usko overwrite kar dega. Force rename.
Toh simple words me: "Meri current branch (master) ka naam badal ke main kar do."

Kyun zaroori hai: Agar tum ye step skip kar do, to tumhari branch master rahegi, aur jab tum git push origin main karoge to Git kahega "main naam ki koi branch hi nahi hai." Confusion se bachne ke liye main standard rakhna best hai.

Check karne ka tareeka:

git branch
Ye dikhayega kaunsi branch pe ho — * main aana chahiye.

2. git remote add origin https://github.com/TUMHARA-USERNAME/selenium-ci-demo.git
bash
git remote add origin https://github.com/TUMHARA-USERNAME/selenium-ci-demo.git
Isko 3 hisson me todo:

a) git remote
"Remote" = koi door ki location (GitHub server) jahan tumhara code store hoga. Ye tumhare computer pe nahi, internet pe hoti hai. git remote ek command hai jo in locations ko manage karti hai.

b) add origin

add = naya remote add karo.
origin = naam of that remote. Ye koi fixed keyword nahi hai — tum kuch bhi naam de sakte ho (jaise github ya myrepo). Lekin convention se sab origin naam rakhte hain. origin ka matlab bas "jahan se mera code originally aata jaata hai."
Ek project me multiple remotes ho sakte hain (jaise origin + upstream), lekin abhi tumhe sirf ek chahiye.
c) URL part
Ye tumhare GitHub repo ka address hai:

bash
https://github.com/TUMHARA-USERNAME/selenium-ci-demo.git
Zaroori note: yahan TUMHARA-USERNAME ko apne actual GitHub username se replace karna hai. Jaise agar tumhara username rahul123 hai to:

bash
git remote add origin https://github.com/rahul123/selenium-ci-demo.git
Aur selenium-ci-demo wahi naam hona chahiye jo tumne GitHub pe repo banate waqt diya tha.

Ye command kya karti hai: Ye sirf tumhare local Git ko batati hai ki "ek remote hai, uska naam origin hai, aur uska address ye hai." Bas bookmark set karti hai — abhi kuch upload nahi hota.

Verify karne ke liye:

git remote -v
Output aayega:

bash
origin  https://github.com/rahul123/selenium-ci-demo.git (fetch)
origin  https://github.com/rahul123/selenium-ci-demo.git (push)
Agar -v (verbose) me same URL dono lines me dikh raha hai, matlab remote sahi set hua.

Agar galti se galat URL add ho gaya: Pehle hatao, phir add karo:

csharp
git remote remove origin
git remote add origin <correct-url>
3. git push -u origin main
css
git push -u origin main
Yahan 3 cheezein hain:

a) push
Tumhare local commits ko remote (GitHub) pe upload karta hai. Yani jo tumne git commit se apne computer pe save kiya tha, ab wo GitHub pe jaata hai aur duniya ko dikhta hai (repo private na ho to).

b) origin
Kis remote pe bhejna hai? → origin (jo tumne abhi add kiya).

c) main
Kaunsi branch bhejni hai? → main.

Toh matlab: "meri main branch ko origin (GitHub) pe push karo."

Ab -u kya hai? Ye important hai:

-u ka matlab hai --set-upstream.

Pehli baar jab tum git push -u origin main karte ho, Git tumhari local main branch ko remote origin/main se link kar deta hai.

Iska fayda kya: Agli baar se tumhe pura git push origin main likhne ki zaroorat nahi. Sirf:

perl
git push
likhne se hi kaam ho jayega. Git ko pata hoga ki kahan bhejna hai. Isi tarah git pull bhi directly kaam karega.

Toh -u = "ek baar link set kar do, future me shortcut mil jayega."

Pura flow ek jagah (mental model):
Table
Command	Kya karta hai	Kahan asar padta hai
git branch -M main	Branch ka naam master → main	Sirf local
git remote add origin <url>	GitHub ka address bookmark karta hai	Sirf local (link set)
git push -u origin main	Local commits GitHub pe bhejta hai + link permanent	Local + GitHub dono
Ek common galti ka dhyan
Agar git push karte waqt password maange, to:

GitHub ne 8 August 2021 se password-based auth hata diya hai. Tum apna GitHub account password daal ke push nahi kar paoge.
Uski jagah Personal Access Token (PAT) chahiye:
GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token
Scope me repo select karo
Token copy karo (ye password ki jagah daalna hai, ek hi baar dikhta hai)
Ya phir SSH key setup karo (thoda advanced, but long-term me better).
Agar push pe error aaye to exact error message bhej do, main dekh ke batata hoon kya issue hai.
